# Share Taskwarrior planning and deadline fields

tsk stores the user's planned work date in Taskwarrior's `scheduled` attribute and the deadline in `due`. We chose these existing fields over separate tsk-only planning metadata so that planning through tsk remains meaningful to the terminal workflow, while keeping an intended work day distinct from a deadline. Taskwarrior interprets `scheduled` as the earliest opportunity to work; tsk labels it Scheduled. The interface originally called it planned day; the label was changed following user review without changing the stored attribute or date semantics. Today and Upcoming rules are recorded in [the product brief](../product-direction.md). See [the date-semantics research](../research/filters-and-reminders-feasibility.md).
