# Widgets and shared participant changes

The `TskWidgets` WidgetKit extension (`com.julesseguin.tsk.widgets`) displays Today or a registered built-in, project, or saved custom task view. The native AppIntent configuration queries current device-local definitions through the central shared factory. Saved selections retain their UUID and resolve the current expression on every timeline read. An unavailable/deleted selection, invalid schema/expression, unavailable App Group, or unreadable storage produces an error entry; it never substitutes Today or another replica.

Rows use `CompleteTaskIntent` and the common Core completion method, including occurrence rules and raw-attribute preservation. The intent awaits the durable local commit. Common synchronization policy is requested afterward; network availability is not represented as a condition of successful local completion. Read-only task states have no completion button. Timeline refreshes use the next query evaluation where available, bounded between one and fifteen minutes; errors request a later retry. WidgetKit schedules and budgets actual refreshes. Interactive AppIntent execution triggers a timeline reload, and every shared change publication requests `WidgetCenter.reloadTimelines`.

## Shared change seam

`TaskChampionSession.makeManager/open` injects `LocalTaskChangeStore` in the same App Group replica directory used by tasks, views, and local schema. `TaskManager.changeVersion()` and `changeUpdates()` expose current task/view/schema revision UUIDs. The stream yields an initial version and then changes, uses a newest-only buffer, and polls the tiny atomic revision file every 500ms while the participant is observing. It does not poll SQLite or carry task payloads. Consumers reread public Core snapshots. The app observes only while active and always reloads on foreground/reopen, recovering changes missed while suspended.

Local commits publish after durable adapter success even without sync configured. View/schema-only changes advance their own token and never request task synchronization. A dedicated cross-process file lock protects revision read/modify/write independently of the network/SQLite admission gates. Publication failure does not convert a true durable save into a retryable capture failure; `changeVersion/Updates` instead surfaces the refresh failure, preventing duplicate capture retries.

Task revisions include their publication origin (`local`, `synchronization`, or `partialSynchronization`). Sync rereads final replica state after both return and error/cancellation, and publishes changed records even when upstream left durable partial state before failing. A separate `successfulSynchronization` token advances only after a successful sync return, including a later success with no additional task changes. Future notification reconciliation must distinguish that success token from partial reception; publication origin is the latest observation trigger, not a guarantee that every field changed by a concurrent attempt came exclusively from the server. System integrations should reuse this central factory/public revision seam and extend the common native publication point for their OS refresh request, rather than attaching only to app scene closures.

Revision UUIDs are invalidation hints, not a history or guaranteed background delivery service. Processes can terminate between a durable commit and hint publication; app foreground/reopen and WidgetKit timeline rereads are recovery paths. iOS does not promise instant background execution. Sync failure before a readable final snapshot cannot prove received membership; a later successful read/foreground reload is required. Locked protected storage remains an explicit unavailable state until first unlock.

## Signing

Main app, Share, and Widget targets use `TSK_APP_PROVISIONING_PROFILE`, `TSK_SHARE_PROVISIONING_PROFILE`, and `TSK_WIDGET_PROVISIONING_PROFILE` respectively. Release installation validates all three explicit bundle IDs, team, shared App Group, nonexpired Ad Hoc distribution, matching device lists and a common distribution certificate before installing any. ExportOptions maps all three bundle IDs to their own profile name. Existing app signing prerequisites remain the configured gate. Once configured, missing extension profiles fail the build with the required secret/bundle information.

Required profile secrets are `APPLE_PROVISIONING_PROFILE` (app), `APPLE_SHARE_PROVISIONING_PROFILE`, and `APPLE_WIDGET_PROVISIONING_PROFILE`; every profile must authorize `group.com.julesseguin.tsk`. Actual distribution signing still requires the account/profile repair tracked by the parent implementation; ad hoc simulator signing does not establish device installation.

## Verification and evidence

Core tests exercise local-only publication, rejection, refresh-ledger failure after a true save, final received-state success/partial-failure provenance, byte-exact registered project identity and current saved expressions. Native checks use real TaskChampion persistence, independent factories, an actual separate process and the actual completion AppIntent, reopening saved definitions and preserving opaque fields. The held GET/accepted POST regression uses the shared factory so durable publication is included in the prompt-write assertion.

`WidgetUITests` installs the native widget through Springboard, reads the default shared App Group, invokes the actual widget completion control, verifies the app's completed row, configures a saved custom view and verifies deletion produces an error. It runs in both canonical iPhone/iPad lanes. Its fixture writes real tasks and definitions in the default shared group of the disposable CI simulator; it has no alternate widget dataset or test-specific extension environment. Fixture JSON and `WidgetCenter.getCurrentConfigurations` identities are retained with screenshot attachments. Artifact checks require the embedded WidgetKit extension, native configuration/completion metadata and actual Mach-O App Group entitlement, alongside the existing Share and App gates.

Local simulator runtime and screenshots were not captured: local boots are prohibited during this disk-constrained implementation. A generic signed build and host intent execution do not prove Springboard rendering, widget configuration, background scheduling or physical device behavior. Canonical CI must supply the system-entry runtime evidence before those checks can be reported as passed.

Primary platform contract: [Apple: adding interactivity to widgets](https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities), [configurable widgets](https://developer.apple.com/documentation/WidgetKit/Making-a-Configurable-Widget), and [AppIntentTimelineProvider](https://developer.apple.com/documentation/widgetkit/appintenttimelineprovider).

The initial full Native run exposed an existing test scheduling problem after adding shared-participant coverage: the timed native exercise ran on MainActor alongside synchronous Taskwarrior CLI fixture helpers. The original five-second deadline, every held-response assertion and concurrent full suite remain intact. No production executor workaround or test serialization was introduced.
