# Calendar in Today (#29)

Calendar is a separate, read-only section in the predefined Today view. It does not appear in Unfinished, Upcoming, Completed, custom views, or widgets. Project selection filters tasks; Calendar continues to show the current day's events. Calendar rows have no task identity or editing/completion actions. Existing task capture, selection, editing, active-state controls and completion still use TaskManager.

`TaskManager.todayCalendar(from:requestingAccess:)` uses its injected clock and Calendar to form the local half-open day window. A day can be 23 or 25 hours. Events crossing midnight retain their original dates and expose clipped visible dates plus earlier/later-day indicators. All-day events sort first, then visible start/end and byte-exact title/calendar/event identity. An occurrence is identified by calendar ID, event ID and original start, independently of task UUIDs. Canceled/outside-day events are excluded; duplicate/invalid entries are disclosed. Calendar reads never query or mutate the task replica.

Access is requested only by tapping Allow Calendar access. iOS provides no read-only Calendar permission: reading requires full access, including the `NSCalendarsFullAccessUsageDescription` key. The production adapter implements only authorization, permission request, and event reads. It has no Calendar save/remove/time-block API. Denied, restricted, write-only, unavailable and request errors remain explicit; tasks remain available. Revocation clears stale events. Refresh runs when entering Today, returning to the foreground, changing time zone/significant time, crossing midnight, or receiving `EKEventStoreChanged`. Pull to refresh reloads tasks and Calendar independently.

`EventKitCalendarSource` owns its EKEventStore in an actor. Its synchronous, day-bounded `events(matching:)` query converts EKEvent objects into Sendable snapshots without suspending or transferring mutable EventKit objects. Authorization is checked before and after the read, and the store resets before fetching and after permission grant. EventKit's synchronous event query has no OS error result; the adapter can detect authorization, invalid-window and malformed-event failures. A separately labeled DEBUG protocol error tests the failure UI; it is not evidence of an EventKit OS failure channel.

Apple primary sources: [Calendar access](https://developer.apple.com/documentation/eventkit/accessing-the-event-store), [requesting full access](https://developer.apple.com/documentation/eventkit/ekeventstore/requestfullaccesstoevents(completion:)), [synchronous event reads](https://developer.apple.com/documentation/eventkit/ekeventstore/events(matching:)).

## Verification

The public Core seam covers DST boundaries, clipping, all-day/multi-day events, recurring occurrence identity, deduplication/malformed entries, explicit permission, revocation, read failure/recovery and unaffected task completion. Native tests use the real TaskChampion replica, compare SQLite bytes before/after Calendar reads and errors, reopen tasks with raw attributes unchanged, and execute snapshot validation on a background executor without requesting Calendar access or reading host calendars.

`CalendarTodayUITests` runs in both canonical iPhone and iPad coverage. Its DEBUG-only fixture requires a UUID token, explicit isolated-simulator flag, full Calendar access and a LOCAL Calendar source. It saves only its own named fixture calendar, records actual stored events, and compares source readback after production-adapter reads. It exercises timed/all-day/spanning events, exact day boundaries, actual EventKit change notification, relaunch/foreground, genuine TCC reset/denial, and task capture after denial. A separate scenario injects a labeled protocol error and completes an ordinary task. Fixture JSON is harvested before the runner shuts down its owned disposable simulator; fixture cleanup targets only the token's calendar. There is no personal-account fallback.

At implementation handoff, Core, focused native checks and signed generic App/UI compilation passed. No local simulator was booted. Actual Calendar source availability, storage readback, permission interactions, notifications, screenshots and iPhone/iPad layout await canonical CI execution. The report explicitly lists missing before/after captures for Today and surrounding task flows. No live personal account, physical device/keyboard, background refresh guarantee, release provisioning, or visual acceptance is claimed.
