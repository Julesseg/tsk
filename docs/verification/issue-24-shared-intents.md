# Shared storage and native task intents (#24)

Create Task and Find Tasks use `TaskManager` and the same TaskChampion replica as the app. Results carry the persistent Taskwarrior UUID. Create returns after the local commit and requests the existing automatic synchronization policy; its dialog says “Saved locally” and does not claim that a server has acknowledged the task. Find searches descriptions and applies the selected status. The app registers both actions through its App Shortcuts provider and links to Shortcuts from its native help screen. Storage, validation, and network errors remain genuine errors.

## Storage and migration

The app and participating processes resolve `group.com.julesseguin.tsk` with Apple's [App Group container API](https://developer.apple.com/documentation/foundation/filemanager/containerurl%28forsecurityapplicationgroupidentifier%3A%29). Failure to resolve the group produces a visible error and Retry. There is no private-storage fallback. Test replicas use separate names inside the group.

The application migrates the complete legacy Application Support/TaskChampion directory, including the replica, operation history, and connection configuration. Files are copied into a task-owned staging directory while a filesystem migration lock and the source's semantic/local operation locks exclude participating writers and interrupt a network-held source transaction. The staged replica must open and return the same UUIDs and byte-exact attributes. Connection configuration is validated under the lock. The copied files and directory are synchronized before an atomic rename publishes the shared-ready marker. The original directory is retained for recovery; a retirement marker makes subsequent operations through that old path fail rather than fork the dataset. Incomplete staging can be retried; an uninitialized destination containing existing data fails explicitly.

An extension must not initialize an empty shared dataset before the app can migrate its private data. `TaskChampionSession.participantDirectory()` requires the shared-ready marker. The normal factory also detects an `.appex` host and uses that restriction. A participating process arriving during migration waits on the migration lock. App Intents hosted in the application can perform the application's migration before their first operation. Future widget/share targets must use the participant factory.

The entitlement must also be enabled on the app's Apple Developer App ID and its device provisioning profiles. Future extensions need their own signed targets with the same group. The existing release lanes still use their configured profiles and do not strip the entitlement. No Developer account capability or device profile was changed or verified here. The simulator UI lane uses ad-hoc signing. A combined generic arm64 simulator build passed for the app and XCUITest targets. Readback from the final Mach-O `__TEXT,__entitlements` section contains the App Group. The simulator code-signature entitlement dictionary itself is empty, so inspecting that dictionary alone is insufficient. Generated app metadata contains Create Task, Find Tasks, their UUID entity, and two App Shortcuts. `scripts/verify-intents-artifact.py` checks those generated artifacts in the canonical UI lane. These artifact checks do not prove container access on a running simulator or device provisioning.

## Process coordination

The native bridge uses filesystem `flock` admission and a synchronized generation file. A local operation records its priority before waiting for the replica operation lock. An active synchronization polls that generation, cancels the upstream future, and drops TaskChampion's transaction before the local operation proceeds. A second sync waits without competing with admitted local operations. Process death releases kernel locks, and SQLite recovers the abandoned transaction. This retains upstream encrypted TaskChampion synchronization and its retry behavior, including an accepted POST whose reply never reaches the client; no second dataset or custom merge protocol is introduced.

TaskChampion 3.1.0 holds an immediate SQLite transaction during server awaits, including its nominal read-only access mode. Merely detaching the network call or adding a Swift actor cannot provide prompt durable local writes. Actual reads also need admission; status streams themselves remain SQL-free. Repeated real reads can interrupt a sync, and the common Core coordinator makes one deferred retry after interruption.

A separate filesystem semantic lease encloses each Core mutation's read, validation, and commit across managers and processes. This includes capture, edits, completion, and dependency add/remove. Each successful mutator calls `localChangeWasCommitted()` after durable commit. The lease is released without awaiting network work. New direct mutators must use `beginMutation()`/`endMutation(_:)`; an action delegating to an existing Core mutator must not acquire a nested lease. External account/network inputs must be gathered before acquiring it. Low-level replica calls are an adapter seam, not an alternative place to implement task rules. Locks coordinate participants using this adapter; arbitrary legacy binaries that bypass it are not covered.

## Actual evidence

The isolated host suite passed 36 Core tests and 30 Native tests with a real TaskChampion bridge, Taskwarrior 3.5.0, and the task-owned encrypted server fixture. Native tests execute Apple's actual `AppIntent.perform()` implementation on macOS, create/find/complete/reopen through the shared Core facade, reject invalid descriptions, and show that a captured intent task automatically reaches an independent replica using the saved connection.

A separate-process HTTP barrier fixture holds a real GET response, a real server-accepted HTTP 200 POST response, and then kills a sync owner after another accepted POST. A different process commits its edit before each held response is released. Retry converges to one UUID with its edit and opaque field intact. The pre-change bridge failed the local-write requirement by waiting 5.23 seconds for the barrier. Failed CAS POST replies are forwarded immediately so the barrier specifically observes an accepted write.

The opposing-edge fixture launches two child executables that call the real `TaskManager.addDependency` API against the same native SQLite replica. Its read barrier gives the uncoordinated control two stale snapshots, which commit a cycle. With the semantic lease, the second process cannot read until the first commits and its real Core call returns `dependencyCycle`. It does not reproduce validation in the fixture. The fixture also checks the original opaque attribute. The CI Native lane builds this executable and runs the same race test.

Migration tests verify identity, annotations, distinct composed/decomposed field names, saved connection, retained source, rejection of writes through the retired source, invalid-configuration preservation, and extension-first initialization failure. The pre-guard bridge failed the extension-first test with three issues and hid the existing private task behind an empty group; the new guard passes.

Logs and isolated fixture artifacts live under `/tmp/tsk-issue-3/issue-24/`. Relevant files are `admission-red.log`, `participant-red.log`, `core-final.log`, `native-final.log`, `app-signed-build.log`, and the native build logs. The unique host library is `libtsk_taskchampion-shared-final.dylib` in that directory. No personal task store, sync settings, account data, or already running simulator was changed.

## Runtime and system gaps

The canonical XCUITest lane includes an installed-app scenario that invokes the real create intent through an explicit Debug test entry, checks its task in the app, relaunches, and opens the Shortcuts help screen. That test entry is not a Shortcuts/Siri system invocation. Local simulator execution and captures were intentionally omitted because of disk pressure; no simulator was booted for this ticket. Actual iOS execution of that scenario awaits CI. The successful-server synchronization XCUITest also remains skipped until the hosted lane provisions its own real isolated server and propagates `TSK_UI_SYNC_*` to the test runner; the local loopback fixture cannot serve hosted CI.

A direct `perform()` test and metadata extraction do not prove that Shortcuts has discovered the actions, that its parameter/result screens render correctly, or that physical Siri dictation works. Those system-surface checks, iPhone/iPad screenshots, signed-device App Group access, locked-device behavior, and real background execution remain unverified. Apple documents discovery and execution through the [AppIntent interface](https://developer.apple.com/documentation/appintents/appintent) and [App Shortcuts registration](https://developer.apple.com/documentation/appintents/acceleratingappinteractionswithappintents); implementing those APIs does not replace this remaining acceptance evidence.
