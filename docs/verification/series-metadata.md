# Series metadata editing

A recurring template has a separate **Edit series metadata** action. Ordinary occurrence editing remains **Edit occurrence**. The series flow supports description, project, priority, tag additions/removals, editing existing template annotations, adding one series annotation, and locally defined typed attributes. Only fields changed by the user propagate. Unregistered and unchanged typed values remain preserved; local allowed-value lists and their order are not changed or synchronized.

Preview lists the template changes and each affected existing occurrence with its due date and field changes. It captures a precise cutoff instant: only pending occurrences due on or after it are eligible. Completed/deleted history and overdue pending occurrences are excluded. A preview writes nothing; Cancel writes nothing. Save applies only reviewed changes. A changed dataset or definition set, or an affected occurrence becoming overdue before save, requires a fresh preview. The template’s updated metadata is inherited by later externally generated occurrences.

Each record’s tag changes are normalized against its own existing tags, so occurrence-only tags outside the edited delta survive. New series annotations use a timestamp not already used anywhere in this series; occurrence-only notes are preserved. Changed existing annotation references keep their timestamps. Adding an annotation and editing template annotations does not replace each occurrence’s entire annotation list. Date, dependency, identity and recurrence fields use their dedicated actions and cannot be changed by this metadata API.

## Atomicity and scope consistency

The public `TaskManager.previewSeriesMetadata` / `applySeriesMetadata` pair uses the common filesystem semantic lease. Apply first validates the preview and local definitions. `TaskAtomicSnapshotMutatingReplica` then supplies the entire expected replica (all UUIDs and byte-exact attributes) to the native transaction guard. The native adapter compares that readset inside the serializable SQLite transaction before committing upstream TaskChampion operations once for the template and affected occurrences. This catches a newly inserted child or an overdue child moved into the future after Core’s revalidation. It contains no recurrence/date rules in Rust.

The old `updateAtomically` primitive remains available. The new native command is `updateSnapshotAtomically`; an older bridge rejects it instead of silently ignoring a required snapshot. There is no sequential fallback. Whole-replica comparison is deliberately conservative: an unrelated task change can require re-preview. Guarded series reads load the upstream task data in one read transaction, followed by the guarded commit transaction, avoiding a whole-replica scan per affected task. The cost scales with the dataset and reviewed batch; a scoped optimization must preserve phantom protection.

No recurrence rule, date, parent link, index or mask is rewritten by metadata propagation. No new occurrence is generated on the device. Local atomicity is not a distributed transaction or custom synchronization conflict policy; TaskChampion’s upstream synchronization semantics remain unchanged.

## Verified behavior and limits

Evidence under `/tmp/tsk-issue-3/issue-22` includes public Core previews, no-write cancellation semantics, typed validation and allowed-value order, atomic storage behavior, actual native writes injected after Core revalidation, and an encrypted Taskwarrior 3.5.0 / real TaskChampion sync-server 0.7.1 round trip. Native series changes propagate to existing future occurrences and the next actual generator-created occurrence while completed attributes/UUIDs, recurrence mask, links and unfamiliar attributes remain intact. Actual HTTP GET and server-accepted POST responses are held while the local atomic series save finishes; retry converges at an independent peer.

A live fixture initially exposed two test assumptions: `45m` is months in the pinned duration grammar, so minutes are written `45min`; an annotation timestamp `1` is not exportable through the pinned Taskwarrior date parser, so real fixtures use full epoch timestamps. Failing logs were retained and fixtures corrected; production parsing was not approximated or weakened.

Signed generic simulator App/XCUITest compilation and embedded App Group/Intent metadata are verified separately from runtime interaction. `SeriesMetadataUITests` covers validation, preview, cancel, save and persistent reopen with a recorded real generator fixture plus controlled completed history. It runs in the canonical iPhone and selected iPad lanes. Runtime screenshots, device/physical-keyboard execution, system Siri/Shortcuts discovery and account/background behavior remain separate pending evidence. No local simulator was booted.
