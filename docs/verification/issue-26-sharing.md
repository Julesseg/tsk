# Native text and URL sharing

The installed **Add to tsk** share extension accepts text and web URLs through the system share sheet. The editable form includes a title, retained text/links, project, priority, tags, planned day, deadline and waiting date. It reuses the main app's native organization and planning controls from `App/SharedTaskForms`. Planned and deadline fields remain distinct. A body containing multiple lines and a URL is retained in a standard timestamped Taskwarrior annotation; the initial title comes from the first nonblank line or URL. The user can edit both title and retained annotation before saving. No attachment bytes are loaded/stored. File-URL providers are ignored, and a direct file-URL Core request fails explicitly.

`TaskManager.sharedDraft` is a pure draft preparation operation. It writes nothing; Cancel only cancels the extension request. `captureSharedTask` constructs one compatible task and uses the common `create` path, including validation, filesystem semantic lease, durable native commit and automatic synchronization hook. The extension finishes its system request only after that commit succeeds. An error keeps the editable draft on screen and permits retry. No failed write is reported as a saved task.

The extension opens `TaskChampionSession.participantDirectory()` and the common configured manager. It cannot migrate a private store, initialize an unready App Group, silently fall back to private data or create another replica. Extension-first use reports that tsk must be opened once, while retaining the source draft. No per-extension synchronization configuration is introduced. Local save does not wait for network responses. Synchronization is best effort during the extension's execution opportunity; upstream local operations remain durable and normal app opening/retry handles later convergence. Extension termination does not promise a completed server exchange.

## Installed targets and signing

`TskShare.appex` is embedded in `Tsk.app`, uses `com.apple.share-services`, declares text/web-URL activation, and has bundle ID `com.julesseguin.tsk.share`. Both targets require `group.com.julesseguin.tsk`. The share target enforces application-extension-safe APIs. Its Release profile specifier is `$(TSK_SHARE_PROVISIONING_PROFILE)`, separate from the main app and widget. A distribution profile must match the share App ID, team, certificate/device set and App Group. A profile without that capability is a real release failure; entitlements and configured release checks remain required. The widget/signing slice owns the common per-target provisioning installer/export map. App Store automatic provisioning still requires the share App ID/capability and suitable API-key authorization; no credentials were requested or read here.

`TskShareFixture.app` is a separate test source app. It presents an ordinary `UIActivityViewController` with synthetic text/URL and has no TaskChampion or App Group access. It is built for testing, not archiving, and is not embedded in the production app. The canonical wrapper builds the app/extension/fixture, installs the source app, then runs `ShareCaptureUITests` first on the freshly created isolated simulator, before any default shared-store initialization. This proves genuine extension-first failure without deleting data or routing the extension to a test-only dataset. The same test opens tsk, exercises cancellation and editable/validation/save flows through the actual installed extension and system share sheet, then reopens the main app to inspect the durable task and annotation. Remaining UI classes run afterward with the share class skipped once. Sharing results are separately retained in `App/TestResults-sharing.xcresult` alongside the existing result bundle. The script requires an explicit derived-data path and result path; use a fresh owned simulator rather than reusing a personal initialized dataset.

## Verified boundaries

Public Core tests cover editable draft preparation, exact retained Unicode/text/URL, no-write preparation, unsupported input, validation and compatible content/organization/date creation. Actual native NSItemProvider callbacks feed the draft; a participant manager writes and a separately opened app manager reads the identical durable task. An operation-log trigger injects a real SQLite save error, proves no acknowledged new task or changed existing task, then permits a successful retry with the same content. A configured common factory automatically synchronizes through a real isolated sync-server to an independent peer, and actual Taskwarrior 3.5.0 export confirms the UUID, multiline Unicode annotation/link, project, tag and separate scheduled/due dates.

Native adapter/provider execution is separate from installed system-extension discovery and UI behavior. Signed generic App/XCUITest builds and embedded entitlement/activation checks are compile/artifact evidence. Canonical iPhone/iPad runtime execution, screenshots, physical keyboard/device, third-party app representation variants, release provisioning and real background opportunity remain separate evidence. No local simulator was booted. The machine-local HTML report lists uncaptured states explicitly and contains no synthetic screenshots. Evidence lives under `/tmp/tsk-issue-3/issue-26`.
