# Cadence and schedule transitions

**Change cadence or schedule** is separate from occurrence editing and series metadata editing. It previews an explicit transition: retire the old template now, create a separate active template, and move the reviewed existing future unfinished tasks to that new template. Completed and deleted history, and unfinished tasks before the effective cutoff, retain their original template and UUIDs. Retired templates remain visible with a history/unfinished-occurrences view; retained unfinished occurrences can still be edited, started/stopped or completed. Ordinary pending lists exclude templates.

The cutoff is the later of the requested effective date and preview time. Preview shows the old UUID, the new template UUID, every moved existing UUID, before/after due/planned/wait dates, and the next unfilled generator position. Cancel writes nothing. Save retires the old template immediately; this is not a delayed activation job. A changed dataset or a reviewed task becoming overdue requires another preview. The new template is separately visible, including after reopening. No persistent lineage field is added and no logical-series continuity is implied.

## Why a separate successor

Keeping an old mask prefix and inverse-shifting an anchor cannot generally produce an arbitrary new first future calendar date: sequential month-end clamps through February cannot recover March 31. Overwriting cadence with the original anchor changes index dates. Resetting the mask regenerates history. The supported transition keeps the old mask length and all unaffected positions; only moved slots become `X`. New-template positions represent the existing moved UUIDs, starting at zero. Its mask is absent when no tasks move. New occurrences remain exclusively the designated external generator's responsibility.

A new synced custom lineage attribute would alter Taskwarrior's UDA/`+ORPHAN` behavior. Built-in `parent`/`template` links would misclassify a template as an occurrence. Neither is added. The old template's opaque attributes and identity remain, but its status, end, modified and moved mask positions explicitly change. Completed occurrence records remain byte-for-byte unchanged. Moved records retain opaque/metadata fields and UUIDs; their parent/index/cadence/date bookkeeping changes explicitly. The successor inherits template metadata, including unfamiliar attributes.

## Version and calendar contract

The implementation targets pinned Taskwarrior 3.5.0, TaskChampion 3.0.0 and sync-server 0.7.1. The user must choose the actual designated generator's IANA time zone and keep the generator configured consistently. It is an input to local preview, not synced custom metadata or a command to reconfigure another client. Only one designated client should generate occurrences.

The shared duration lexer is reused, but recurrence stepping preserves the pinned generator's branches. Monthly/numeric month/quarter rules clamp sequentially; January 31 can become February 28 and then March 28. `monthly` and `P1M` preserve clock time. Generic ISO month durations such as `P2M` and `P3M` reset subsequent clock times to midnight. Named quarterly periods preserve clock time. Named yearly/`P1Y` clamp leap day to February 28, while `biannual`/`biyearly`/`P2Y` normalize leap day to March 1; numeric `2years` uses fixed seconds. Daily/weekly durations use fixed seconds and can change local clock time across DST. Weekdays use the generator's local weekday and fixed-day seconds. Planned/wait dates independently preserve each task's offset, clear, or adopt a chosen common offset from due; scheduled and due remain distinct.

The old generator must already cover positions before the cutoff. Missing unfinished mask positions, or an ungenerated old slot before the cutoff, fail with an instruction to run and sync the designated generator. This avoids silently discarding missing old-cadence work when retiring a template. Invalid masks/links, unsupported recurrence types, invalid time zones/offsets/dates and overflow fail without writes. A calendar-projected nonexistent or repeated local clock time fails explicitly; fixed-second DST crossings are supported. Dates must be positive epoch seconds through year 9999. Until must cover the reviewed moved occurrences. Pinned Taskwarrior can generate its first occurrence beyond Until and retire an ended all-waiting template while pending waiting children remain; those children remain accessible and actionable.

## Atomicity and synchronization

`TaskManager.previewSeriesTransition` and `applySeriesTransition` use the common filesystem semantic lease. `TaskAtomicTransitionReplica.commitAtomically` requires a complete expected replica plus creates and per-record conditional updates. The new native `commitSnapshotAtomically` command compares the byte-exact whole replica inside the upstream serializable SQLite transaction and commits all TaskChampion operations once. This includes the new template creation, old retirement and existing child updates, task maps, working set and operation log. There is no sequential-update or older-bridge fallback. Whole-replica comparison is conservative and linear in dataset size: unrelated changes can require re-preview. Upstream TaskChampion conflict and encrypted synchronization semantics remain unchanged; local atomicity is not a distributed transaction.
