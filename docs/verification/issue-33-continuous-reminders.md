# Continuous Reminders move

The native compact More menu and iPad sidebar offer Move from Reminders automatically. Selected source lists map to projects through the same reusable controls as one-time copy. Enabling explicitly designates this device and starts a move; other installations default to disabled. The operating settings stay in device-local shared storage, outside task synchronization. The stored vendor device identifier is checked before automatic execution, so a configuration restored onto a different device cannot silently enable it there. If a device identifier, permission, list or configuration is unavailable, moving fails visibly and ordinary task management remains available.

Core owns configuration, eligibility, destination creation, move results, single-attempt admission and failure pausing. TaskManager.runContinuousReminderImport loads the designated-device settings and calls the same field mapping as one-time copy. It uses common TaskManager.create for every valid destination, with the semantic mutation lease, durable native commit and synchronization hook. Only after create returns successfully does it invoke the candidate's transient removal capability. A failed destination write never invokes removal. Cancellation between stores preserves the source and reports the saved task. A failed removal stops the attempt immediately and pauses automatic retries in memory; callbacks cannot immediately recopy the failed source. Explicit retry or restart can create a duplicate. The UI explains this accepted trade-off and never promises exactly-once or a transaction across stores.

There are no processed reminder IDs, per-item suppression sets, provenance fields, source-derived task UUIDs, import-history file or retained source markers. Candidates hold only a transient snapshot/removal closure during one attempt. Settings persist selected list IDs, project mappings and the designated device only. Results remain session UI state and are not written as import history. Metadata configuration saves use the same semantic lease and do not trigger task sync.

The production EventKit adapter rechecks full authorization and re-fetches the current source immediately before removal. It compares byte-exact title, notes and URL, list, priority, completion, both date components, and a complete recurrence signature containing selectors, ordinals, first weekday, calendar and end conditions. A changed, unavailable or no-longer-writable source is retained with a failure. Adding a recurring rule after fetch is therefore protected too. After remove(commit: true), the adapter resets its cache and requires absence readback. EventKit offers no atomic compare-and-remove operation spanning task storage; an external edit in the final check/commit window cannot be ruled out by this implementation.

All incomplete priority bands remain eligible. Completed, unselected, invalid and unverified recurring reminders stay outside movement. Full recurrence conversion remains #34 and requires returned actual EventKit rule/sequence evidence; no frequency-label inference is made here.

## Execution opportunities

The app scans on foreground entry and debounced EventKit changes. Concurrent observer callbacks are ignored during an active controller attempt, and Core independently rejects a concurrent move on the same manager. Failure pausing prevents self-generated callbacks from immediately retrying the failed source. A Stop action cancels the current attempt; Core checks cancellation before task creation and before source removal. Source-list and project settings can be disabled explicitly.

The existing registered BGAppRefresh opportunity now attempts configured Reminders movement before optional server synchronization, including local-only task storage. It reuses the active controller when available, otherwise opens the same central shared manager. Expiration cancels movement and suspends synchronization. Completion reports genuine configuration/import failures. iOS chooses when or whether to grant background execution; this does not promise instant ingestion or a fixed rescan period. Foreground/source-change opportunities remain available if scheduling fails.

## Verification

Public Core tests cover durable-save-before-removal observations, successful movement, genuine destination failure with no removal, stopping and pausing after removal failure, automatic retry suppression without ID bookkeeping, explicit duplicate-producing retry, designation mismatch, disable, and cancellation immediately after durable create. The isolated native tests use an independently reopened TaskChampion manager inside the removal capability to establish committed state, verify persisted configuration and mode0600, verify another device remains disabled, and exercise an actual native filesystem failure. The existing one-time native reopen/Taskwarrior export test also passes after the adapter/common mapping changes.

Canonical ContinuousReminderImportUITests run on iPhone and explicit iPad coverage, preserving every prior lane class. They use the real isolated #32 local EventKit fixture, actual production removal and readback, observed source changes and foreground availability. A DEBUG simulator-only checkpoint pauses between durable save and removal: one scenario actually edits the source into a recurring series before resuming and verifies preservation plus pause; another terminates the app and resets real authorization in that window, reopens the saved task, then grants access and verifies original sources. No forced successful fake adapter replaces EventKit. Own fixture writes are guarded by the isolated-run flag; no personal account is used as a fallback.

With per-operation live permission revalidation, a signed SDK27/iOS26.5 iPad run reached the original weekly-move result “Saved 1; removed 1; skipped 1; failed 0.” Five distinct native permission requests returned true while static authorization remained undetermined. The test then failed revealing its verification button, before source-history and durable-template assertions; this is partial provider evidence, not a completed move acceptance test. The interruption/actual-authorization-reset scenario has not yet run with the changed adapter, and the full canonical lanes remain required.

Existing Core and native evidence establishes durable-save ordering and failure handling; generic compilation alone does not establish EventKit deletion scope or background delivery. No host personal Reminders data was touched. Physical device/keyboard, iCloud/Exchange and closed-app scheduling remain unverified.
