# Shared continuous Reminders admission

All native managers made by TaskChampionSession.makeManager share an import-only filesystem gate in their task directory. A move holds it across a single finite source fetch, durable task creation and source revalidation/removal. A second window or process waits before fetching. This gate is independent of the ordinary semantic mutation lease: each durable create uses that existing short lease, while EventKit work holds only the import gate. Ordinary capture, editing and settings remain available during source work. Waiting is cancellable; exiting the owner process releases its operating-system lock.

The central factory injects LocalContinuousReminderStore as configuration and admission provider. Core clients using another backing store can inject a shared ReminderImportCoordinating implementation; ReminderImportCoordinator supplies in-memory admission for that purpose. Direct moveReminders calls also acquire admission, while automatic runContinuousReminderImport checks designation, current mappings and shared pause after acquiring it. Automatic source callbacks never clear a failure pause. Settings are rechecked before each save and removal; changed settings retain the source and stop the attempt.

The directory contains one source-free operational marker, continuous-reminders-paused, whose entire content is the literal `paused`. It is written before source work starts and cleared only after a fully successful attempt, or explicit configuration change. Save/removal/source-access failure, cancellation during an attempt, and process interruption therefore hold automatic scans across other managers and restart. No source IDs, titles, counts, errors, provenance or attempt/item history are retained. The existing device-local configuration remains enabled/designated-device/list mappings only. Both marker and configuration use private permissions and iOS first-unlock protection.

A visible pause may also mean another window is currently finishing an attempt. Settings explain this, show a cancellable waiting/moving state, and distinguish loading lists. All active windows refresh only configuration/pause metadata every second; this does not query SQLite or interrupt sync. They also read current state on foreground and at scan admission. A stopped queued request does not modify another attempt's pause marker. Explicit Scan / Retry or re-enabling is an acknowledged new attempt: it can create duplicates if a prior task was saved while its source remained. Cross-store crash/retry atomicity and guaranteed background timing are not promised.

One-time copying and personal source accounts are unaffected. Import-source identifiers used by the EventKit adapter remain transient memory handles for safe deletion. The marker is operational admission state, not per-item bookkeeping.

## Verification

Public Core tests hold source fetch while independent managers compete, require ordinary capture to finish, and check only one imported task. They cover queued cancellation, disabled settings while queued, and a failed destination pausing another manager. Native tests use separate real TaskChampion managers, a genuine SQLite commit fault, restart/readback, explicit retry, private marker readback, and cancellable queued admission. Separate executable processes share one owned source fixture and directory; only the admitted process may fetch before release, normal concurrent moves save once, deletion failure pauses the second process, and ordinary capture remains available during the held fetch.

The existing isolated EventKit UI interruption/permission scenario now verifies a persisted pause on relaunch and explicitly requests retry before expecting the revoked-access error. Actual multiwindow UI, EventKit runtime, screenshots, physical devices and background timing require canonical/device evidence; generic compilation does not establish them.
