# Verified recurring Reminders import

Both one-time copying and continuous moving can create a real Taskwarrior recurring template from one verified EventKit rule. The template starts at the source's current incomplete occurrence, not the first historical occurrence. Completed Reminders history is excluded. Notes, URL, project and priority use the ordinary import mapping; no source identity, import history or provenance is stored. Each template receives a new UUID.

## Supported contract

The source must be a local EventKit source (type0) with exactly one Gregorian weekly rule, interval1, firstDayOfWeek2 (Monday), no weekday/monthday/yearday/yearweek/month/set-position selectors, and no end date/count. Its start and due must contain equal full Gregorian calendar dates with explicit GMT, 09:00:00, no fractional seconds or independent date selectors. Calendar dates are checked strictly, and the positive Unix anchor must leave room for another period. The serialized rule must contain exactly the recognized fields. Missing/unknown metadata, multiple rules, other source types, date-only values, named daylight-saving zones, independent start/due offsets, selectors, intervals and end conditions remain unsupported with a visible reason. No approximation or flattening is used.

The rule maps to `status=recurring`, `rtype=periodic`, `recur=1week`, with due and scheduled anchored at the current incomplete source date. Creation uses TaskManager.createRecurringTemplate, its common semantic mutation lease, normalization, native durable commit and automatic-sync hook. Before continuous deletion the returned record must confirm valid template fields. Existing EventKit removal separately re-fetches and compares the full source snapshot/rule/list/completion/source kind and writability before removal. Shared-directory import admission/failure pause remains in force. Ordinary task writes never hold their semantic lease across EventKit work.

Copy leaves all source content intact. Continuous mode removes only the verified current recurring remainder after the valid template is saved. The actual local source experiment establishes that completed history remains; external-account deletion scope has not been established, so those sources are excluded from this supported recurring mapping. Unsupported items remain intact in either mode. An interrupted move or explicit retry can still leave duplicates; no cross-store atomicity is claimed.
