# Newly learned missed notifications (#31)

After a successful encrypted synchronization, tsk considers original planned/due events from its immutable final snapshot, excludes already known or accepted constituents, and intersects the candidates with the latest durable tasks. A completed/deleted task, removed original date, or recurring template cannot create a missed alert. A later partial state can suppress an older candidate, but cannot introduce a new missed candidate. Current device preferences and calendar determine effective times; raw task dates, identity and byte-distinct attributes stay unchanged. Equal effective times combine only the remaining eligible constituents.

The native adapter retains `synchronization-receipt.json`: a first-use baseline and the latest successful snapshot with a unique boundary and completion time. Creation/read of an absent baseline is atomic under existing replica operation admission; synchronization creates it before starting network work. Final capture and atomic receipt publication occur after TaskChampion commits and before that operation guard releases. There is no network-duration semantic mutation lease and no change to the TaskChampion server protocol. Failed/interrupted attempts do not replace the successful receipt. If receipt persistence fails after TaskChampion commits, received tasks remain durable and the failure is visible; missed discovery waits for a later successful receipt. The pinned TaskChampion transaction rolls back received changes when cancelled before its final commit, including an accepted POST response held by the fixture proxy.

Every local semantic writer passes its actual saved records to the awaited post-commit effect after releasing task admission. This includes ordinary capture/edit/complete, activity, annotations/dependencies, imported tasks, template capture, occurrence bookkeeping and series batches. Those exact records settle their original event tokens; a broad read cannot accidentally settle a foreign partial arrival. Notification decisions stay in Core. Native participants use the same shared App Group receipt and notification ledger through the central factory; host factories do not access the host user's notification center.

`task-notifications.json` serializes reconciliation across processes. Newly learned missed candidates become a durable retry queue before submission. Explicit native rejection or denied permission stays retryable even without another sync. Before adding an immediate request, Core persists an attempting record; a genuine successful native add moves each constituent to accepted. If the process stops or persistence fails between those operations, pending/delivered readback can positively confirm acceptance. Without positive evidence the attempt remains visibly uncertain and is not automatically resent. Moving a fallback time or splitting a combined display cannot replay an accepted or uncertain original event. A changed constituent does not discard an unchanged sibling. Multiple failed requests remain individually retryable.

An accepted registration is not proof that the user saw it. Notification Center readback contains only currently visible items, so absence cannot distinguish a dismissed delivery from a never-delivered request. The implementation makes no exactly-once OS-delivery claim. Pending cancellation cannot retract an alert already triggered; remote completion cannot affect this device until its state arrives. The settings UI distinguishes accepted date events, retryable missed alerts, uncertain outcomes and future registration errors, and exposes reconciliation retry.

New ledger fields are optional for backward decoding. Existing #30 known/accepted entries are preserved conservatively: their previous local/partial origin cannot be reconstructed. Missing first-use baseline metadata is initialized atomically from the native pre-sync dataset. Malformed ledger/receipt data fails visibly and is never reset to an empty success. Receipt writes use private permissions, file/directory fsync and atomic replacement; iOS sets first-unlock protection on the replica directory, and notification-ledger writes retain their existing protected atomic-write policy.

## Evidence and runtime limits

Core public-manager tests cover final-state suppression, local versus partial provenance, delayed success versus newer partial records, fresh-manager repeat suppression, genuine rejection retry without a new receipt, combined/split preference identity, interrupted acceptance, partial constituent changes, multiple failures and series save context. Native checks use real TaskChampion SQLite, a real encrypted server/independent replica, receipt-file failure and corruption, cancelled accepted POST, reopened central factories and two independent notification-reconciliation processes. The OS boundary is controlled in host tests; no host personal UN center is read or written.

`MissedNotificationUITests` is compiled into the canonical disposable iPhone/iPad lane. It requests/restores real system authorization, uses an independently encrypted native peer and separate authorized client, receives missed pending plus completed/deleted tasks in one genuine final sync, requires actual delivered combined readback, relaunches without reseeding, checks stable actual delivery timestamps and original acceptance timestamps after no-change sync, then receives remote completion and verifies future cancellation. Fixture JSON contains raw records, immutable receipts, accepted events, pending/delivered IDs and actual delivery dates. The existing notification tests retain scheduled closed-app delivery, permission revocation/restoration and actual registration-capacity readback. Share-first initialization, both result bundles and prior coverage remain intact.

Local execution verifies compilation and the Core/native contracts, not iOS delivery or appearance. Canonical screenshots, actual UN delivery, real Settings navigation, physical-device Focus/lock behavior and unscheduled background opportunities require their respective runtime evidence. The single-file UI report explicitly lists missing before/after captures.
