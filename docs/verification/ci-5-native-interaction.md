The ranked keyboard hypotheses were malformed input, an absent/disabled focus command, and text-input precedence. Actual synthesized command events rule out malformed input; the failed scene path cannot reliably provide actions in either empty workspace or focused TextEditor. The correction installs explicit responder-chain commands and priority for only the app's declared shortcuts. Standard text-editing combinations remain native. Editor-suspended Command-N is consumed without being advertised as an available action. Working workspace capture/edit/selection/completion/view/refresh shortcuts retain titles for discovery.

The host is per window, not an application-global current-task registry. View-backed command scopes register only while attached to that window, so dismissing an editor releases its save closure. No source data or task description is logged or exposed as keyboard diagnostics. Ordinary panels continue to suppress workspace task actions.

Apple documents [responder-chain routing, including presentation back to the presenting controller](https://developer.apple.com/documentation/uikit/using-responders-and-the-responder-chain-to-handle-events), [key commands](https://developer.apple.com/documentation/uikit/uiresponder/keycommands), and [priority over text input/focus](https://developer.apple.com/documentation/uikit/uikeycommand/wantspriorityoversystembehavior). These establish the supported implementation seam, not proof that the corrected app has executed.
